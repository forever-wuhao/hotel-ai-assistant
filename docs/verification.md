# 本地验证记录

日期：2026-11-16。环境：Windows、Microsoft OpenJDK 17.0.17、Maven 4.0.0-rc-5、Node.js 24.14.0；浏览器为 Playwright Chromium。后端是 `demo` 配置，H2 与虚构酒店政策，无外部服务密钥。

| 验证项 | 结果 | 范围 |
| --- | --- | --- |
| `mvn test` | 17 项通过 | 酒店/预算/发布状态筛选；逐夜库存；政策隔离；会话重放与并发；失败重试；引用校验；缓存更新 |
| Spring AI 协议 | 已通过 | 实际 Spring AI 客户端连接本地伪供应商，执行 2 次工具、3 次模型交互，验证工具序列化、观察回传和 Embedding 协议 |
| `npm run build` | 通过 | Vue/TypeScript 类型检查及生产构建；修复原仓库现有类型错误 |
| Playwright | 5 项通过 | 实际浏览器调用本地后端；匿名咨询、旧管理员 Token 隔离、多轮改预算、来源展开、刷新恢复、过期会话重置、失败重试、移动布局 |
| 场景评测 | 20/20 场景通过 | [实际输出](../evaluation/latest-demo.json)，含多轮场景与预期失败场景 |

浏览器错误恢复测试：在已成功建立的会话中拦截一次 HTTP 503，再放行重试到真实本地后端；确认重用 requestId，不重复显示用户消息，供应商原始错误文本不出现在页面。过期会话测试使用无效会话标识，收到服务端 409 后需要显式重置。匿名咨询不需要登录，也不发送本地缓存的管理员凭证；没有把匿名功能宣称为登录/刷新令牌全链路已验证。

场景中共 20 次工具调用，其中 17 次成功；3 次预期失败分别为未发布酒店、无效日期和未配置地图服务。这些失败处理正确，因此对应场景通过。不能把原始工具成功率与任务通过率混为一谈。

延迟数值由报告记录，受本机缓存、热身与并发影响，只反映离线演示。演示模型本身是规则脚本，20/20 不能写成 GLM 任务完成率、RAG 检索准确率或线上成功率。

已视觉检查桌面及 390px 宽手机页面截图，无横向溢出，来源卡片、错误提示及输入区域正常显示。截图由 `vue-admin/tests/assistant.spec.ts` 产生在被 Git 忽略的 `vue-admin/test-results/`。

尚未验证：真实 GLM/Embedding 账户与返回质量、高德真实路线、生产 MySQL 数据/迁移、原管理端完整业务、Android 真机。真实调用需要自行配置凭据和资料后另跑联调与人工评测。没有模型训练或微调成果。
